## 1. Вход как человек

Проверено скриптом (раздел `login` в JSON): «Войти» на главной → `/vhod/` → для каждой роли пустой телефон, маска, «Получить код», неверный код, код 4815 → свой раздел; чужой раздел; «Сменить роль»; выход; возврат по `next`; регистрация компании; 390 px.

**Что работает хорошо.** Маска телефона, ошибки полей, неверный код, 4815 → правильный раздел для всех трёх ролей, защита чужих разделов (редирект на вход с пояснением «Вы вошли: … (закупщик)»), возврат на исходную страницу после входа, выход из панели на главную с удалением сессии. На `/vhod/` уже есть блок «Демо-доступ: войти одним нажатием» с тремя карточками ролей — новый человек теперь находит все три кабинета без подсказки.

**Сможет ли новичок догадаться?** Закупщик — да («Войти» в верхней полосе). Поставщик — да («Кабинет поставщика» в верхней полосе и подвале). Оператор — только если дошёл до `/vhod/`: на витрине нет ни одной ссылки на панель. На телефоне «Войти» спрятана в бургер.

## 2. Сквозной обход закрытых страниц

__CRAWL__

Методика: 71 закрытая страница (`kabinet/**`, `kabinet-postavshchika/**`, `panel/**`) под нужной ролью, ширины 1440 и 390. Однотипные страницы (12 заказов, 12 заявок поставщика, 11 сделок, 7 клиентов) кликаются по 2 первых, остальные — загрузка + проверка ссылок (`--full` кликает все). Элементы шапки/подвала витрины кликаются один раз на роль и ширину (`DUP_CHROME`). localStorage перед каждой страницей восстанавливается снимком (только сессия роли). Навигация перехватывается, адрес проверяется HTTP-запросом.

Классы результата в JSON: `NAV` / `NAV_SELF` / `NAV_404` / `HASH` / `MODAL` / `TOAST` / `STUB_TOAST` (заглушка «демо») / `DOM` / `DOWNLOAD` / `NATIVE_DIALOG` / `DEAD` (ничего) / `INPUT_NO_REACTION` (поле не сохраняется и ни на что не влияет) / `DISABLED`.

**Ошибок JS и 404 не найдено** — ни при загрузке, ни при кликах; битых ссылок из кабинетов нет.

### 2.2 Заглушки «демо» (кнопка есть, действия нет)

- `/panel/zhurnal/` и журнал в админке — «Откатить» у записей из макета: «Откачено … (демо: в макете значение не хранится)» — значение на экране не меняется, но запись помечается «откачено». → `admin.js rollback()`: для `rec.macro` не показывать кнопку или отключить с подсказкой. **P2**
- `/panel/**` — все оставшиеся `[data-demo]` кнопки дают ««…» — выполнено в демо-режиме, запись добавлена в журнал» (`admin.js leftovers()`); «Позвонить (демо)», «Переотправить (демо)», «Выбрать вариант… (демо)». Список по страницам — в JSON (`result: STUB_TOAST`). **P3**

## 5. Доступность (кратко)

- Модальные окна поставщика и панели: `dialog`/`role=dialog`, фокус переходит внутрь, Esc закрывает, фокус возвращается — **ок** (проверено на 120 открытиях).
- Поповер «Что нового» (`role=dialog`): фокус остаётся на кнопке, внутрь не переходит. **P3** → `bus.js` (открытие поповера: фокус на первый элемент, Esc/возврат фокуса).
- Подписи полей: на всех закрытых страницах у полей есть `label`/`aria-label`; иконки-кнопки подписаны; дублирующихся `id` нет; видимый фокус есть.
- Кликабельные строки без фокуса: `tr[data-href]` на `/kabinet/zakaz-pk-10428/` (3), `/kabinet-postavshchika/` (6), `/panel/admin/` (1) — не достигаются с клавиатуры. **P3** → убрать `data-href` со строк (см. 2.8) либо `tabindex=0` + Enter в `site.js`.
- Меню пользователя: `role=menu`, стрелки, Esc — ок.
- Переключатель ролей на `/vhod/`: `role=radiogroup`, стрелки — ок.
