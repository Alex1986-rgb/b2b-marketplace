## Главные причины (что показал «до»)

| Причина | Факт | Вклад |
|---|---|---|
| Google Fonts через `@import` в `ds.css` | цепочка HTML → ds.css → fonts.googleapis.com → gstatic; CSS шрифтов блокирует отрисовку | **~1 с** render-blocking на мобильном, главный тормоз |
| `app.css` 167 КБ (30 КБ gzip), блокирующий | 80 % правил не используются на конкретной странице (≈134–150 КБ) | ~0,6 с на мобильном |
| Шрифты | 8 файлов woff2 ≈ 220 КБ (кириллица+латиница, 3 начертания Fira Sans + 2 Condensed) | CLS от подмены шрифта, 2 внешних домена |
| inline `style="…"` | 48 тыс. атрибутов на 195 страниц, 3,85 МБ сырого HTML | в gzip мало (сжимается хорошо) |
| DOM | 307–1024 элементов | в норме (порог ~1400) |
| JS | site/search/auth.js — все `defer`, TBT 0 | не проблема |
| Картинки | фоновые, WebP через image-set, первые 3 eager, остальные лениво | в норме |

## Что сделано (`tools/perf_postprocess.js`, `postprocessSite(siteDir)`)

1. **Шрифты.** `@import` Google Fonts вынут из `ds.css` и поставлен в `<head>` ссылкой с неблокирующей загрузкой
   (`media="print" onload="this.media='all'"` + `<noscript>`). `display=swap` уже был, preconnect уже был.
   Цена: на главной мобильный CLS 0,024 → 0,075 (всё ещё «хорошо», порог 0,1) — подмена системного шрифта на Fira.
   Отключается опцией `{ fontsAsync: false }` (тогда ссылка блокирующая, но без звена через ds.css).
2. **Минификация CSS** (app.css 167 → 152 КБ, gzip 29,6 → 25,7 КБ; ds.css 12 → 9 КБ) — только комментарии и пробелы
   + удаление более ранних точных дублей блоков (дублей сейчас 0). Lightningcss пробовал: +0,4 КБ выигрыша, но
   переписывает значения (color-mix → hex) и даёт расхождения computed style — отказался.
3. **inline-стили → классы** `.s<N>` в `assets/inline.css`: 154 класса, 26 697 атрибутов на 124 страницах,
   −1,4 МБ сырого HTML (−10–20 % на страницу; в gzip −0,3…0,9 КБ, inline.css 1,9 КБ gzip кешируется).
   Каскад эквивалентен inline: `:where(.sN){…!important}` первым стилем страницы. Программно исключаются:
   значения, которые матчат селекторы `[style…]` из всех CSS/`<style>`/JS (99 таких в app.css); регулярки JS по
   `getAttribute('style')` (url(, width:14px, z-index, margin-left:auto, position:absolute); свойства из `@keyframes`;
   `url()`/`!important`; элементы `data-bg`/`data-photo`; страницы с admin/cabinet/vendor.js (71 шт. — там JS
   копирует и переписывает style); `catalog.js` нового каталога проверен (style не трогает) и внесён в белый список. Из 194 кандидатов отбраковано 40. Повторный прогон на той же папке — пропуск.
4. **defer** — проверено: все внешние скрипты с `defer`, inline-JS нет (только JSON-LD).
5. **LCP-картинка** — `optimizeImages` корректен: preload первой WebP с `fetchpriority="high"`, у hero — `media`
   только для десктопа. На мобильном LCP чаще текст (H1/лид), на карточках — фото-блок `.ph`; менять не нужно.

`tools/qa/lighthouse.js` — прогон 9 страниц × 2 профиля, свой статик-сервер с gzip (`--serve <папка> --gzip`),
сводка `lh-summary.json` (оценки, FCP/LCP/TBT/CLS, DOM, render-blocking, топ-аудиты) + сырые LHR.

## Хук для `tools/build_site.js`

```js
  // перф-пост-обработка готовой папки: шрифты неблокирующе, inline-стили → классы, минификация CSS
```
