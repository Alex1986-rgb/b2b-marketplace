## Что сделано

1. **Замер** 5 ключевых страниц в headless Chrome (puppeteer-core, CDP Network `encodedDataLength`, полная прокрутка страницы; LCP/CLS через PerformanceObserver). Два вида: desktop 1440×900 DPR 1 и mobile 390×844 DPR 2. Отдельно сделан прогон «медленный 4G (1,6 Мбит/с, 150 мс) + CPU×4». Скрипты замера лежат в scratchpad: `perf/measure.js`, `perf/fold.js`, `perf/cov.js`.
2. **Размеры показа.** Обошёл все 135 страниц `site/` в двух вьюпортах и для каждого `project/img/*.jpg` снял максимальный фактический размер показа (`background-size: cover` → с учётом высоты блока).
3. **Пережатие.** Новый скрипт `tools/optimize_images.py`: из `project/img/src/*.png` делает прогрессивный JPEG (ImageMagick, q76, 4:2:0, без метаданных) и рядом `.webp` (cwebp q74, -m 6). Ширины: p-* — 900, крупные сцены — до 1600 (исходник 1536, увеличения нет), остальные сцены — 1000, nameplate — 800. `og-cover.jpg` исходника не имеет, поэтому ему только lossless-перепаковка `jpegtran -progressive`. `tools/compress_photos.py` теперь просто обёртка над новым скриптом.
4. Готовые файлы скопированы в `site/img/`, чтобы снять замер «после». Сборщик при следующем прогоне скопирует их сам: `copyDir` берёт всё, кроме `src`.
5. **Визуальная сверка** до / после / webp на кадрах hero-pump-hall, p-cr32-flange и a-valves при одном масштабе: разницы на глаз нет. Картинки на сайте к тому же идут под duotone-фильтром.

**Главная проблема дальше не в весе, а в порядке загрузки.** Все фото — это `background` в inline-стилях. Браузер находит их поздно и качает все сразу, включая 11–16 картинок ниже первого экрана. Hero делит канал со всеми остальными, поэтому LCP главной и блога на медленной сети — 8+ секунд. Решение — пункты A–C ниже: preload hero, image-set с WebP и ленивая загрузка фона.

## Что нужно сделать в сборщике (готовые фрагменты)

Эти файлы не в моей зоне правок, поэтому ниже только код.

### A. WebP через image-set + ленивая загрузка фона + preload hero — `tools/build_site.js`

Обработка идёт на уровне готовой HTML-строки. Так она покрывает и снимки макета (`inPage`), и страницы из `gen_pages.js`. Первые 3 фото на странице грузятся сразу, первое из них ещё и предзагружается. Остальные уходят в `data-bg`, их подгрузит site.js.

```js
// рядом с page(): оптимизация фоновых фото в готовом HTML
const IMG_SRC_DIR = path.join(SRC, 'img');
const EAGER = 3; // столько фото в начале страницы грузим сразу (hero / первый ряд карточек)
function optimizeImages(html) {
  let i = 0, preload = '';
  const body = html.replace(
    /(<[a-z][a-z0-9]*\b[^>]*?)style="([^"]*?)url\((&quot;|'|)([^"')&]*?\/img\/([\w-]+)\.jpg)\3\)([^"]*)"/g,
    (m, tag, pre, q, jpg, name, post) => {
      if (/gradient/.test(pre + post)) return m;            // фото поверх градиента не трогаем
      const hasWebp = fs.existsSync(path.join(IMG_SRC_DIR, name + '.webp'));
      const webp = jpg.replace(/\.jpg$/, '.webp');
      const set = hasWebp
        ? `image-set(url(${webp}) type(&quot;image/webp&quot;), url(${jpg}) type(&quot;image/jpeg&quot;))`
        : `url(${jpg})`;
      const n = i++;
      if (n === 0 && hasWebp) {
        // .hero-ph скрыт на ≤760px — на телефоне hero не предзагружаем
        const media = /hero-ph/.test(tag) ? ' media="(min-width: 761px)"' : '';
        preload = `<link rel="preload" as="image" href="${webp}" type="image/webp" fetchpriority="high"${media}>\n`;
      }
      if (n < EAGER) {
        // старые браузеры не поймут image-set(type()) и оставят JPEG из шортхенда
        return `${tag}style="${pre}url(${jpg})${post.replace(/;?\s*$/, '')}; background-image: ${set};"`;
      }
      return `${tag}data-bg="${set}" data-bg-jpg="${jpg}" style="${pre}${post}"`;
    });
  return body.replace('</head>', preload + '</head>');
}
```

Подключить во всех местах, где пишется страница: строки ~240, 263, 272, 277. Проще всего завести обёртку:

```js
const writePage = (file, html) => fs.writeFileSync(file, optimizeImages(html));
// fs.writeFileSync(file, html)  →  writePage(file, html)   (и для 404, gen-страниц, extra-страниц)
```

Картинки для фона `.webp` сборщик уже копирует: `copyDir(project/img → site/img)`.

### B. Ленивая подгрузка фона — `tools/site/site.js` (в конец файла)

```js
// Ленивые фоновые фото: data-bg проставляет сборщик (optimizeImages)
(function () {
  var els = document.querySelectorAll('[data-bg]');
  if (!els.length) return;
  var webpSet = window.CSS && CSS.supports && CSS.supports('background-image', 'image-set(url("a.webp") type("image/webp"))');
  function show(el) {
    el.style.backgroundImage = webpSet ? el.getAttribute('data-bg') : 'url("' + el.getAttribute('data-bg-jpg') + '")';
    el.removeAttribute('data-bg');
  }
  if (!('IntersectionObserver' in window)) { els.forEach(show); return; }
  var io = new IntersectionObserver(function (entries) {
    entries.forEach(function (e) { if (e.isIntersecting) { show(e.target); io.unobserve(e.target); } });
  }, { rootMargin: '600px 0px' }); // начинаем качать за ~1 экран до появления
  els.forEach(function (el) { io.observe(el); });
  window.addEventListener('beforeprint', function () { document.querySelectorAll('[data-bg]').forEach(show); });
})();
```

Скрытые слайды карусели (`display:none`) подгрузятся сами в момент показа: IntersectionObserver сработает, когда слайд станет видимым.

Ожидаемый эффект:
- на первом экране грузится 80–460 КБ фото вместо 0,9–1,5 МБ;
- с WebP это ещё примерно −45 %;
- LCP главной и блога на медленном 4G должен упасть с ~8 с примерно до 2–3 с. Цифру нужно перемерить после внедрения.

### C. Шрифты (116–221 КБ на страницу — самый тяжёлый текстовый ресурс)

Сейчас подключены Fira Sans 400/500/600/700 и Fira Sans Condensed 400/500/600 с Google Fonts. Скачанный Google CSS в покрытии показывает 0 % использования: он весь из `@font-face`. Файлы шрифтов качаются по кириллическому и латинскому поднаборам. Что сделать:
1. Сократить начертания до реально используемых. Condensed, вероятно, достаточно одного 600 для цифр и цен — проверить по `app.css`.
2. Для hero-заголовка добавить preload одного woff2:
   `<link rel="preload" as="font" type="font/woff2" href="…/fira-sans-600-cyrillic.woff2" crossorigin>`.
   Для этого woff2 нужно хранить у себя (`site/assets/fonts/`) и объявить `@font-face { font-display: swap; unicode-range: U+0400-045F, U+0490-0491, U+2116; }`. Это же уберёт два лишних соединения с fonts.googleapis/gstatic.

### D. Минификация app.css — низкий приоритет

Покрытие CSS по всем 135 страницам:
- app.css — используется 85 %;
- ds.css — 60 %.

Выгода от вычистки неиспользуемого мала: 15 % от 17,8 КБ gzip. Простая минификация даёт 17,8 → 15,5 КБ gzip. Дёшево, можно добавить в строку ~289:

```js
const minCss = s => s.replace(/\/\*[\s\S]*?\*\//g, '').replace(/\s+/g, ' ')
  .replace(/\s*([{};,>])\s*/g, '$1').replace(/;}/g, '}').trim();
fs.writeFileSync(path.join(OUT, 'assets', 'app.css'), minCss(styles + '\n' + /* …как сейчас… */ ''));
```

`:` не трогаем: минификатор на регулярках ломает селекторы вида `a :hover`. PurgeCSS не рекомендую: классы создаёт site.js (корзина, фильтры, меню), и риск отрезать нужное выше, чем 2–3 КБ выгоды.

### E. Повторяющиеся inline-стили — средний приоритет, только с визуальной сверкой

На главной 637 атрибутов `style` — 50 КБ сырого HTML. 46 разных значений встречаются больше двух раз и вместе занимают 40 КБ. После gzip выигрыш около 5–8 КБ на страницу.

**Риск:** класс слабее inline-стиля, и правила из skin.css начнут перебивать то, что сейчас перебить не могут. Делать только со скриншот-сравнением всех страниц.

```js
// после сборки всех страниц: частые style → классы .s0, .s1… в конец app.css
function hoistStyles(pages /* [{file, html}] */) {
  const cnt = new Map();
  for (const p of pages) for (const m of p.html.matchAll(/ style="([^"]{40,})"/g)) cnt.set(m[1], (cnt.get(m[1]) || 0) + 1);
  const map = new Map([...cnt].filter(([s, n]) => n >= 20 && !/url\(/.test(s)).map(([s], i) => [s, 's' + i.toString(36)]));
  let css = '';
  for (const [s, c] of map) css += `.${c}{${s.replace(/&quot;/g, '"')}}\n`;
  for (const p of pages) p.html = p.html.replace(/(<[a-z0-9]+)([^>]*?) style="([^"]{40,})"/g, (m, tag, attrs, s) => {
    const c = map.get(s); if (!c) return m;
    return /class="/.test(attrs) ? tag + attrs.replace(/class="/, `class="${c} `) : `${tag}${attrs} class="${c}"`;
  });
  return css;
}
```
