# Отчёт: иерархия заголовков и контекстная перелинковка (15.09.2026)

План: `docs/plans/2026-09-15-perelinkovka-i-zagolovki.md`, пункты 1–3 и 5 (аудит, пост-обработка, проверка).

## Что сделано

1. **Аудит `tools/qa/seo_structure.js`** — работает по файлам `site/` без браузера (<1 с). Считает h1, пропуски уровней,
   заголовки в header/footer/nav, пустые заголовки и дубли h1, исходящие и входящие внутренние ссылки, сирот,
   «слабые» анкоры (Открыть/Подробнее/→ без aria-label), ссылки на текущую страницу, контекстные ссылки `a.pk-ilink`.
   Запуск: `node tools/qa/seo_structure.js [--site=… --out=… --label=…]`.
   JSON: `docs/reports/seo-structure-before.json` (до), `docs/reports/seo-structure.json` (после).
2. **`tools/seo_postprocess.js`** (хук сборки уже был в `build_site.js`). HTML не пересобирается целиком: парсер
   `node-html-parser` (dev-зависимость) только находит позиции, правки вставляются точечно. 195 страниц — около 0,5 с.
   При ошибке возвращается исходный HTML.
   - **Заголовки:** один h1; заголовки в header/footer/nav заменяются на div; уровни идут без пропусков
     (уровень = min(исходный, предыдущий+1)). Заголовки карточек (`.card-title` и первый «заголовочный» span в
     `a.blueprint`/`.card`) становятся h3, а под разделом h3 — h4. Цены, числа и FAQ-summary не трогаются.
     Если у элемента есть `role="heading" aria-level`, уровень ARIA приводится к новому тегу.
   - **Как сохранён вид.** Предложенный вариант со вставкой inline font-size не подошёл: inline-стиль перебил бы
     классы (`pv-h2`, `pk-cab-h1`, `.card-title`) и мобильные правила `h1/h2 {… !important}` из app.css.
     Сделано так: элементу со сменённым тегом добавляется класс `pk-o<исходный уровень>`, а в `<head>` перед ds.css
     вставляется один `<style id="pk-seo-hx">` (~1,3 КБ). Он возвращает размеры дизайн-системы, контекст
     `.pk-prose h2`/`.pk-prose-col > h2`/`.split > … > h3`, мобильные clamp для бывших h1/h2 и исходный
     размер через `--pk-fs` у бывших h3/h4, ставших h2. У карточек класс `pk-hcard` (inline-отображение,
     наследование размера, margin 0). skin.css не менялся.
   - **Перелинковка** (только публичные страницы). Ссылки ставятся в абзацах `.seo-p`, p/li внутри `.pk-seo`,
     `details.seo-more`, `details.faq-item`, `article`, `.pk-prose(-col)`. Первое упоминание бренда, направления,
     товара или статьи из `ctx.LINKS` становится ссылкой `a.pk-ilink`. Совпадение ищется без учёта регистра, по
     границе слова, неразрывные пробелы учитываются, длинные имена проверяются первыми. Лимиты: 1 ссылка на цель,
     8 на страницу, 2 на абзац. Ссылка не ставится на текущую страницу, внутри a/button/summary/заголовков/таблиц/.mono
     и на цель, на которую уже ведёт обычная ссылка в основном контенте (шапка, подвал и крошки не считаются).
   - **Словоформы убраны** по замечанию обходчика: «насосов» в статье про электродвигатели давало `wrong_target`.
     Теперь ссылка ставится только на точное имя сущности.
   - **Мелкие правки:** `rel="noopener"` у внешних ссылок (на текущих страницах таких нет), `aria-label` у ссылок
     без текста, у «Открыть/Подробнее/→» — `aria-label="Открыть: <строка таблицы или заголовок карточки>"`.
3. **Сборка** — 194 страницы, ошибок в макете 0. `check_site.js`: 0 проблем разметки, 0 в браузерной проверке.
   `crawl_links.js`: 1 ошибка — известная `many_cards_same_target` про `?tip=` на napravleniya/nasosy/.
   Новых ошибок от модуля нет, `wrong_target` = 0.

## Ограничения и что осталось

- **panel/ (закрытые):** уровни заголовков не перенумерованы, осталось 9 пропусков h1→h3. admin.js ищет блоки по
  `h2`/`h3` (`$('h3', b)`, `!$('h3', b)`), смена тегов сломала бы панель. У этих h3 сборщик уже ставит
  `role="heading" aria-level="2"`, для экранных дикторов уровень корректный. Остальные закрытые (kabinet*, vhod,
  korzina) обработаны полностью.
- Заголовки карточек превращаются только на публичных страницах; если перед карточками нет раздела h2, span остаётся span.
- Словоформы не ловятся (решение по обходчику): «насосов», «компрессорам» ссылками не станут.
- Дубль текста h1 в h2 на napravleniya/pozharnoe-oborudovanie/ — это контент шаблона, не трогал.
- poisk/ без входящих — служебная noindex-страница, так задумано.
- **Сборка:** `tools/build_site.js` в текущем виде падает с `DCLogic is not defined`. У подмены React в `rq.respond`
  нет заголовка `Access-Control-Allow-Origin`, и Chrome блокирует скрипт по CORS. Файл не мой, я его не менял;
  собирал через обёртку, которая добавляет заголовок в памяти. В `build_site.js` в `rq.respond({...})` нужно
  добавить `headers: { 'Access-Control-Allow-Origin': '*' }`.
- Не закоммичено. На сервер не заливалось.
